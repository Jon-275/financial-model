Preserve the current Excel formulas and Python reference as separately testable implementations. Share versioned parameters and fixture semantics between them. ## Scenario, annual state and validation

Define these boundary records when the first consumer needs them. `ScenarioSnapshot/v1` contains the active scenario, opening year and balances, horizon, household and account inputs, state and effective policy versions, healthcare assumptions, and market configuration. `RunSpec/v1` adds the scenario identity, generator version, seed, pair count and stress suite version. `RunResult/v1` identifies its run and status, trial and stress outcomes, annual bands, ranked funding ledgers, and computation provenance. Validate types, units, ranges and supported versions at the boundary. Define how blank differs from zero and use stable year, account, scenario and trial IDs. A new incompatible schema gets an explicit version and a tested migration or a clear error.

Use the native typed assumptions signature in `native_capture._context` and a Python run identity composed from `risk_engine/scenario._digest` plus the full validated `RunSpec`. Their encodings may differ. Test that they agree on which edits invalidate a result. Keep currency view, selection of an inspection trial and timing diagnostics outside financial identity. A state or effective policy change invalidates a run. A change to an inactive scenario leaves the active run eligible if every active input still matches. Keep household digests, scenario keys, plans and reports local.

For each modeled year, use the following order in the base projection, conversion analysis and market paths.

```text
opening state + prices + household events + effective policy
  → lawful income and account access for that year
  → candidate draws in the configured funding order
  → candidate taxable income, basis, federal/state tax and payroll
  → healthcare credits, total cash due and feasible draw interval
  → select the earliest feasible candidate under the elected conversion policy
  → commit the selected draws, payments, contributions and returns once
  → reconcile closing state and carry it forward
```

Calculate actual tax and cash results for each candidate, including discontinuities such as Marketplace credit cliffs. The normal projection retries with no conversion only when the requested conversion is infeasible. Roth targeting preserves the requested policy. With no feasible draw, select the best modeled cash margin and use the smallest draw on ties. Carry its unpaid taxes and spending under the existing priority rules. Report the first year with at least one cent unpaid even if a later year pays the balance. Preserve restrictions and owner-level basis, loss and withdrawal ledgers. Reconcile opening and closing quantities, value dates and nominal versus opening-year purchasing power per field. Check exact statuses, identities and first-shortfall dates. Apply the existing numeric comparators to continuous fields and exercise the one-cent boundary separately. ### Quantitative test strategy

- For a performance-only change, require exact RNG vectors, paired identities, stress selection, publication counts, success classification, shortfall dates and rank keys. If the optimization changes reuse decisions, compare eligible cases to independently calculated uncached trials and record the proof. Reconcile numerical columns with existing tolerances, including both real and nominal series and all closing accounts. Exercise zero shocks, withdrawal-cliff cases, first/last trial ID, ties, irregular return/price paths, cuts and no cuts, and long-to-short horizon changes. Test trial ID partitions and reorderings against the serial reference. [Native RNG tests](../../tests/test_native_random.py) · [Calculation order acceptance](../../tests/native_order_acceptance.py)
- For a deliberate statistical model change, version the methodology and pre-register deterministic vectors, fixed seed sweeps and sufficiently large offline fixture tests. Check moments for the modeled return convention, cross-asset correlations including positive-semidefinite edge cases, and inflation behavior including caps and floors. Set thresholds before reviewing results. A historical calibration proposal needs dated sources, independent validation periods and written limitations. Model assumptions and withdrawal policies must remain inspectable.
- Report sample size and conditional model meaning. For fixed or flexible rates, use a Wilson interval if the UX requires a measure of simulation precision. For policy differences, use discordant pairs or a paired bootstrap under the same markets. At a 50% success rate the approximate worst-case normal 95% Monte Carlo half-width is 9.8 percentage points for 100 paths and 3.1 for 1,000. These figures measure sampling variation under fixed assumptions. Use scenario and stress analysis for assumption sensitivity. Measure timing changes on the same model, horizon and sample size.
